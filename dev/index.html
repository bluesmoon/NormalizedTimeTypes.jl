NormalizedTimeTypes.COMMON_TZ_ABBRS — Constant

Internal dictionary of common legacy timezone abbreviations to their full TimeZone names.

We use this dictionary because timezonesfromabbr returns multiple results that all match the offset of the common abbreviation. Rather than pick a random one, we use the most likely candidate based on colloquial usage. For example, "EST" is used in multiple timezones, but the most common usage is "America/New_York". This dictionary is used to disambiguate these cases.

Used by expand_legacy_timezone.

NormalizedTimeTypes.DATE_FORMATS — Constant

Ordered list of (Regex, DateFormat) pairs for parsing timezone-naïve date/time strings.

Each entry matches a specific string pattern and provides the corresponding Dates.DateFormat to parse it into a DateTime. Patterns are tried in order; the first match wins.

Supported formats:

  • yyyy-mm-dd HH:MM:SS[.sss] — space separator, optional milliseconds
  • yyyy-mm-ddTHH:MM:SS[.sss] — ISO 8601 T separator, optional milliseconds
  • yyyy-mm-ddTHH:MM:SS[.sss]+ — trailing + sentinel (offset stripped by caller)
  • yyyy-mm-ddTHH:MM:SS[.sss]- — trailing - sentinel (offset stripped by caller)

Used by NormalizedTimeType for strings without a numeric timezone offset. For timezone-aware strings see DATE_FORMATS_TZ.

NormalizedTimeTypes.DATE_FORMATS_TZ — Constant

Ordered list of (Regex, DateFormat) pairs for parsing date/time strings that embed a numeric timezone offset.

Each entry matches a specific timezone-aware pattern and provides the corresponding Dates.DateFormat to parse it into a ZonedDateTime. Patterns are tried in order; the first match wins.

Supported offset formats (combined with both T-separator and space-separator date-time):

  • ±HHMM — compact offset, e.g. +0400
  • ±HH:MM — colon-separated offset, e.g. -05:30
  • HHMM — space-separated offset, e.g. 0400

Milliseconds are optional in all patterns.

Used by NormalizedTimeType for timezone-aware strings. For timezone-naïve strings see DATE_FORMATS.

NormalizedTimeTypes.NormalizedTimeType — Type

A container type for various views of a given TimeType which, via converters.

  • struct NormalizedTimeType

Fields

timezone::TimeZone : The TimeZone of the contained TimeType.

utc_datetime::DateTime : The UTC converted representation of the contained TimeType.

tz_datetime::ZonedDateTime : A ZonedDateTime representing the contained TimeType and its TimeZone

unix_ms::Int64 : The contained TimeType represented as milliseconds since the Unix Epoch of 1970-01-01T00:00:00.000Z

Constructors

NormalizedTimeType(::TimeType) : Constructs a NormalizedTimeType from a TimeType. The passed in TimeType may be a Date, a DateTime, a ZonedDateTime, or any other subtype of TimeType

NormalizedTimeType(::TimeType, ::TimeZone|AbstractString) : Constructs a NormalizedTimeType from a DateTime with an associated TimeZone. The second parameter may either be a TimeZone object or a string TimeZone name.

NormalizedTimeType(::NormalizedTimeType, ...) : Constructs a NormalizedTimeType from another NormalizedTimeType. This is useful for converting a NormalizedTimeType to a different timezone.

NormalizedTimeType(::AbstractString, ::TimeZone|AbstractString="") : Constructs a NormalizedTimeType from a string representation of a date/time with an associated TimeZone. The second parameter may be excluded if the string representation includes a timezone, or it may be a VariableTimeZone to use instead of a FixedTimeZone parsed from the string.

Will check DATE_FORMATS and DATE_FORMATS_TZ for a suitable parser.

If the object represents a timestamp that falls within a DST transition period of the specified timezone, then this function will attempt to determine the most appropriate value by checking the delta with the DST transition, applying that to the UTC equivalent, and then converting.

Converters

NormalizedTimeType has converters for DateTime, ZonedDateTime, and Int64, so it may be used wherever one of these three types is required.

Operators

You may also add and subtract any Dates.Period or Dates.CompoundPeriod to/from a NormalizedTimeType object to get a new NormalizedTimeType object.

For example:

julia> t1 = NormalizedTimeType(Date(2016, 10, 10))
NormalizedTimeType(UTC,2016-10-10T00:00:00,2016-10-10T00:00:00+00:00,1476057600000)

julia> t1 + Dates.Month(1) - Dates.Day(2)
NormalizedTimeType(UTC,2016-11-08T00:00:00,2016-11-08T00:00:00+00:00,1478563200000)

julia> t1 - Dates.Month(1) + Dates.Week(1)
NormalizedTimeType(UTC,2016-09-17T00:00:00,2016-09-17T00:00:00+00:00,1474070400000)

Examples

julia> NormalizedTimeType(Date(2016, 10, 10))
NormalizedTimeType(UTC,2016-10-10T00:00:00,2016-10-10T00:00:00+00:00,1476057600000)
julia> NormalizedTimeType(DateTime(2016, 10, 10, 1, 2, 3))
NormalizedTimeType(UTC,2016-10-10T01:02:03,2016-10-10T01:02:03+00:00,1476061323000)
julia> NormalizedTimeType(ZonedDateTime(DateTime(2016, 10, 10, 1, 2, 3), tz"America/New_York"))
NormalizedTimeType(America/New_York (UTC-5/UTC-4),2016-10-10T05:02:03,2016-10-10T05:02:03-04:00,1476075723000)
julia> NormalizedTimeType(DateTime(2016, 10, 10, 1, 2, 3), tz"America/New_York")
NormalizedTimeType(America/New_York (UTC-5/UTC-4),2016-10-10T05:02:03,2016-10-10T05:02:03-04:00,1476075723000)
julia> NormalizedTimeType(DateTime(2016, 10, 10, 1, 2, 3), "America/New_York")

NormalizedTimeTypes.normalizeTimestamps — Method

Normalize multiple TimeTypes to NormalizedTimeTypes

  • normalizeTimestamps(t...) → NormalizedTimeType[...]
  • normalizeTimestamps(tz, t...) → NormalizedTimeType[...]

TimeType is the common supertype for DateTime, Date, ZonedDateTime and others.

Arguments

tz::AbstractString|TimeZone : [optional] The common timezone to use for all ts that don't have their own TimeZone

t::TimeType... : The time values to normalize.

Returns

An array of NormalizedTimeType

Example

julia> norms = TimeUtilities.normalizeTimestamps(
           DateTime(2016, 10, 10, 1, 2, 3),
           ZonedDateTime(DateTime(2016, 10, 10), TimeZone("America/New_York")),
           Date(2015, 4, 3)
       )
3-element Array{TimeUtilities.NormalizedTimeType,1}:
 TimeUtilities.NormalizedTimeType(UTC,2016-10-10T01:02:03,2016-10-10T01:02:03+00:00,1476061323000)
 TimeUtilities.NormalizedTimeType(America/New_York (UTC-5/UTC-4),2016-10-10T04:00:00,2016-10-10T04:00:00-04:00,1476072000000)
 TimeUtilities.NormalizedTimeType(UTC,2015-04-03T00:00:00,2015-04-03T00:00:00+00:00,1428019200000)
julia> norms = TimeUtilities.normalizeTimestamps("America/New_York", DateTime(2016, 10, 10, 1, 2, 3), Date(2015, 4, 3))
2-element Array{TimeUtilities.NormalizedTimeType,1}:
 TimeUtilities.NormalizedTimeType(America/New_York (UTC-5/UTC-4),2016-10-10T05:02:03,2016-10-10T01:02:03-04:00,1476075723000)
 TimeUtilities.NormalizedTimeType(America/New_York (UTC-5/UTC-4),2015-04-03T04:00:00,2015-04-03T00:00:00-04:00,1428033600000)
